C317236 lossless job storage — 2026-11-17

Scope: API job persistence only. No aggregation, line splitting, permissions,
customer settings, scheduler, frontend, upload, email or Proof decision changes.

Large jobs are stored as gzip JSON in data.B. Ordinary data.S jobs are unchanged.
Version, byte length, SHA256 and key identities are checked before hydrated data
can be used. Inflation is capped at the declared size, at most 16 MiB. Complete
encoded items must fit within 396 KiB, reserving 4 KiB for existing outer metadata.
All existing job write/read paths use the shared codec; CAS and transactions
remain unchanged. JobStorageError is an internal storage diagnostic, not an
instruction to alter a customer's valid order grid.

Operations: compressed items cannot be interpreted by raw JSON.parse(data.S).
Use decodeDynamoRecord or normal authenticated job APIs. For raw Dynamo lookup,
search contains(data,:identifier) OR contains(job_search,:identifier). The latter
contains only bounded contract/task/job/external-order identifiers and is never
a substitute for the complete record. Legacy replacement/rejected-recovery
tools outside the deployed package fail closed on binary data; do not use them
on compressed records until separately adapted and reviewed.

Rollback: the original pre-codec binary is NOT compatible after compressed writes.
Retain a separately tested compatibility rollback with the decoder and
WRITE_COMPRESSED_JOBS=false. It reads all old/new jobs; small writes remain plain,
while oversized writes fail closed. It is a read-safe recovery posture, not a
claim of full large-order write availability. No lossy reverse migration.
